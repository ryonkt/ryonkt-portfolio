## スライド構成（カルーセル）

### スライド1｜フック
```
「Issue確認→コード修正→PR作成→Slack報告」
この一連の作業、まだ手作業でコピペしてない?

Claude Code"単体"運用はもう古いと言われ始めてる。
外部ツールと自動でつながる「MCP」(AIとアプリをつなぐ共通の窓口)を
使いこなせるかどうかで、非エンジニアの差がつくかも…🥲
```

### スライド2｜① GitHub MCP（公式サーバー）
- **一言**: ClaudeがGitHubに直接ログインして動いてくれる公式の連携ツール
- 🔥**最強ポイント**: 「Issue確認→コード修正→PR作成」まで一気に自動化でき、人の手を介す回数が減ると言われている
- 👶**非エンジニアに何が嬉しい**: 自分でGitHub画面をポチポチ操作しなくてOK。「対応してPRまで作っておいて」と頼むだけで、エンジニアへの進捗確認の往復連絡が減ると言われている
- **導入難易度**: ふつう（最初にGitHubのアクセストークン＝ログイン用の鍵のようなものを1回設定するだけ）

### スライド3｜② Composio Agent Orchestrator
- **一言**: Notion・Slack・Jiraなど100種類以上の外部ツールをAIに繋ぐ「配線盤」的存在
- 🔥**最強ポイント**: コマンド一つで「仕様書を読む→実装する→Slackに報告する」のように複数アプリをまたぐ作業をまとめて走らせられると報告されている
- 👶**非エンジニアに何が嬉しい**: タスク管理はJira、報告はSlack、仕様はNotion…とアプリを行き来しなくていい。指示を出すだけで各ツールに自動で反映される
- **導入難易度**: むずかしい（接続したいツールの数だけ、最初にAPI連携の許可設定＝各アプリへのログイン許可が必要）

### スライド4｜③ Claude Code × GitHub Actions
- **一言**: 自分のPCではなく、GitHub上でClaude Codeを自動起動させる仕組み。公開テンプレートも配布されている
- 🔥**最強ポイント**: PR作成をきっかけに自動でレビューやリファクタ提案が走り、チームのレビュー待ち時間が短くなると言われている
- 👶**非エンジニアに何が嬉しい**: PCを閉じていてもOK。PRを出した瞬間にAIが自動でチェックしてくれるので、「あとで見ておいて」と頼まなくても済むようになると言われている
- **導入難易度**: ふつう（公開されているワークフローファイルをコピーして、鍵＝トークンを設定するだけ）

② 慣れたらComposioで他ツールも接続
③ チーム運用が固まったらGitHub Actionsに載せる

この順番が始めやすいと言われてる。
今すぐ試せなくてもOK、保存して後で見返してね📌

## デザインメモ
全体トーン: ダーク背景(ネイビー〜黒系グラデ)＋差し色は蛍光グリーンorイエロー1色のみで統一(エンジニア/ターミナル感を演出)。フォント: 見出し太字ゴシック、本文は行間広め。1スライドの文字は「見出し1行+本文3〜5行」まで。

- **スライド1(hook)**：大きい数字「100種類以上」を強調配置。その下に小さめの文字で「MCP=AIとアプリをつなぐ共通の窓口」という一言定義バッジを添えて、初見でも意味が分かるようにする。さらに下に煽り一文。
- **スライド2〜4(各ツール)**：上部にツール名+番号アイコン(①②③)、中央に🔥最強ポイントを吹き出し風ボックスで強調、下部に👶非エンジニアメモを別色ボックスで区別。専門用語(アクセストークン/API連携設定など)が出る箇所は、ボックス内に小さめの注釈テキスト(例:「トークン=パスワードのような鍵」)を添える。難易度はバッジ風に色分け(緑=かんたん、黄=ふつう、赤=むずかしい)。
- **最終スライド(CTA)**：チェックリスト風に①②③を並べ、最後に「保存📌」「フォロー🔔」ボタン風のUIパーツを配置。
- **共通**：余白を広めに取り、スマホ1画面で読み切れる文字量を厳守。専門用語には必ず小さな注釈を添え、非エンジニアが読み飛ばさず理解できることを最優先する。
