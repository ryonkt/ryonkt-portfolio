# TikTokプロジェクト ロードマップ（外注用）

> 対象：非エンジニア向け「Claude Code 活用」TikTokシリーズ。
> 制作の詳細仕様は `SPEC.md` を参照。本書は**進め方・スケジュール・担当分担・到達目標**を規定します。

---

## 0. 全体像

- **ゴール**：シリーズ5本を軸に、非エンジニアのClaude Codeユーザーのフォロワー基盤を作る。
- **KPI**：保存数・保存率、フォロー転換（初回ベンチ＝再生2,000超・保存56）。
- **原則**：デザイン・トーンは固定（`SPEC.md`）、投稿ごとに変えるのは文言だけ。週2本を崩さない。

## 1. 役割分担

| 作業 | 担当 |
|------|------|
| 企画・テーマ選定・文言確定 | 発注者（自分） |

## 2. マイルストーン

- **M1：制作基盤の確立（1週目）**
  - `SPEC.md` のClaude Designをテンプレ化（1080×1920）。ライト/ダーク両対応の見本1枚を承認。
  - 投稿2「プラグイン2選」を**パイロット制作** → 発注者レビュー → 品質基準を確定。
- **M2：シリーズ量産（2〜3週目）**
  - 投稿3「MCP連携」制作・投稿。投稿4・5の文言確定 → 制作。
- **M3：総集編と最適化（4週目）**
  - 投稿5「保存版10選」を固定投稿化。反応データを見て勝ちパターンを更新。
- **M4：継続運用（5週目〜）**
  - 反応の良かった回の続編・実演動画。マネタイズ導線の検討。

## 4. 1投稿の制作パイプライン（外注の標準手順）

1. 発注者が**確定台本（文言）**を渡す（`SPEC.md` 付録A / 台本原稿）。
2. 固定テンプレ＋文言で**カルーセルHTMLを生成** → **PNG（1080×1920）書き出し**。
3. CapCutで**動画化**（表示秒数：フック約4s／各ツール9〜10s／CTA約6s、切替ディゾルブ、字幕、AI音声）。
4. **キャプション・ハッシュタグ・導入手順**を添えて納品（`SPEC.md` §9 の命名規則）。
5. 発注者が最終確認 → 投稿。

## 5. 品質チェックリスト（納品前）

- [ ] 1枚目に「Claude Code」が画面最大で入っている
- [ ] 配色・フォントが `SPEC.md` §4 どおり（絵文字・グラデ・囲みなし）
- [ ] 文言が確定台本と一字一句一致（絵文字のみ不使用）
- [ ] 数値が伝聞表現（「〜と言われる／報告あり」）
- [ ] スマホ1画面で読める文字量／セーフゾーン内
- [ ] ライト・ダーク両テーマで破綻なし
- [ ] 動画：縦1080×1920・約35〜40秒・字幕とナレーション同期

## 6. リスク・前提

- ツール名・URL・数値は**投稿前に各公式リポジトリで実在/最新確認**（`SPEC.md` 付録B）。
- 導入手順はREADME準拠でコマンドを断定しない。
- 効果数値は誇張・断定しない（伝聞維持）。誤帰属に注意（例：14%はsuperpowers単体の報告）。

## 7. 完了の定義（Definition of Done・1投稿）

スライド／動画／キャプション／ハッシュタグ／導入手順が揃い、品質チェックリスト全項目を満たし、発注者承認済みの状態。
