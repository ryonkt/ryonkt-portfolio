# TikTok コンテンツ仕様書 ― 非エンジニア向け「Claude Code 活用」シリーズ

> 目的：外部マーケターにレビュー/助言を依頼するための共有ドキュメント。
> 現状の意思決定・デザイン仕様・制作フロー・未確定論点をまとめています。
> 最終更新の反映内容は末尾「変更履歴」を参照。

---

## 1. 概要

- **アカウント方針**：自分でコードは書けないが Claude Code（AIコーディングツール）を使っている「非エンジニア層」に向け、トークン節約・効率化ツールを1本1テーマで紹介する。
- **発信者**：非エンジニアの個人クリエイター（＝ターゲットと同じ立場）。「同じ目線の人が教えてくれる」ことが信頼の源泉。
- **主商材**：情報コンテンツ（将来的な出口＝フォロワー基盤／個人ブランド。現時点で直接の物販・課金はなし）。

## 2. ターゲット

- **主対象**：Claude Code を使い始めた〜使っている非エンジニア（副業・個人開発・業務効率化目的）。
- **インサイト**：「便利だけど、料金（トークン）が知らないうちに増える／待ち時間が長い／専門用語が分からない」。
- **提供価値**：専門知識ゼロでも「コピペ中心で今日から効果を実感できる」ショートカット。

## 3. 現状の実績（検証データ）

- 初回テーマ（トークン節約3選）を **動画形式で投稿 → 2,000再生超・保存56**。
- **学び**：保存率が高い＝「後で使いたい実用情報」として機能。看板テーマとして有効。
- 一方、続編のカルーセルで **1枚目の「Claude Code」表記が小さく反応が鈍化**。→ 下記デザイン原則に反映済み。

## 4. コンテンツ設計

### 4-1. 勝ちパターン（全投稿共通の型）
1. **1枚目（フック）**：`Claude Code` を最大表示で即認知 → 損失・危機を体感させる煽り語1つで刺す。
2. **中間（各ツール）**：ツール名／一言／🔥効果（数字）／👶非エンジニアに何が嬉しいか／導入難易度。
3. **最終（CTA）**：「まず何から？」の結論 ＋ 保存・フォロー誘導。

### 4-2. フック原則（最重要・実データ由来）
- 1枚目は **「Claude Code」を画面最大**に置き、1秒で"自分ごと"と分からせる。
- **文字は極力大きく＝語数は最小**。長い説明は2枚目以降へ。
- **損失を身体感覚で伝える煽り語を1つだけ**使い、アクセント色で強調する。
  - 実績のある語：**溶ける**（トークンが溶ける＝浪費が直感的に伝わり初回で好反応）。
  - 派生の候補：ムダ遣い／消耗／丸腰（無防備）／コピペ地獄。
  - **不採用**：ダダ漏れ（＝情報漏洩を連想させ文脈がズレる）、ダダ減り（造語感）。

## 5. デザインシステム（"Claude Design"・固定）

> **原則：デザインは固定。投稿ごとに変えるのは中身（テキスト）だけ。** テンプレ崩れ防止のため制作フローで固定化（§7）。

- **コンセプト**：ミニマルで上品な編集デザイン。余白重視、装飾は最小。
- **配色**：背景=温かいオフホワイト `#FAF9F5`／文字=ほぼ黒 `#1F1E1C`／補助グレー `#6B6862`／アクセント=テラコッタ `#CC785C`（1画面に1箇所だけ）／罫線 `#E8E5DE`。ダーク対応（地 `#1C1B19`）。
- **禁止**：グラデ・影・光沢・絵文字・吹き出し・バッジ・囲みボックス。区切りは1pxヘアラインのみ。
- **タイポグラフィ（差別化の核）**：**明朝×ゴシックの混植**。
  - 名詞・キーワード・ツール名・数字＝**極太ゴシックで大きく**（主役）。
  - 助詞・語尾・つなぎ＝**明朝で小さく**（脇役）。主役と脇役でサイズ差2〜3倍。
- **判型**：9:16 縦型。1枚1メッセージ。スマホ1画面で読み切れる文字量。

## 6. トーン＆マナー / コンプライアンス

- 効果の数値（削減率など）は開発者・利用者の**報告ベースの目安**。投稿では必ず「〜と言われる」「報告あり」等の**伝聞表現**を使い、断定・誇張を避ける。
- 各ツールは第三者製OSSを含む。**正確な導入手順は各GitHubリポジトリのREADME最新版で確認**する運用（手順スライドでコマンドを断定しない）。
- ツール名・URLは参考情報ベース。実在・ライセンスは投稿前に要確認。

## 7. 制作フロー

1. **固定テンプレ**（デザイン指示）＋**差し替えブロック**（テキストのみ）を用意（社内資産 `TEMPLATE-prompt.md`）。
2. 差し替えブロックの `《 》` に今回の文言を埋める。
3. テンプレ＋差し替えを **AI に1回投げて、カルーセルHTMLを一括生成**（デザインは常に一定）。
4. 生成物を画像 or 動画スライドとして書き出し、キャプション・ハッシュタグ・導入手順を添えて投稿。

## 8. 投稿カレンダー（初期案）

- **頻度**：週2本（火・金 20:00）。
- **順序**：00（投稿済）→ 01 → 02 → 03 → 04（総集編・固定投稿化）。
- **運用**：投稿直後30分はコメント返信で初速を作る。数値は伝聞表記。保存版はプロフィール固定。

## 9. KPI / 測定

- 主指標：**保存数・保存率**（実用情報としての価値）、フォロー転換。
- 副指標：再生数・平均視聴時間・シェア・プロフィール遷移。
- 初回ベンチ：再生2,000＋／保存56。以降はこれを基準に検証。

## 10. 外部マーケターに聞きたい論点（アドバイス依頼）

1. **フォーマット**：静止画カルーセル vs 動画スライド、どちらを主軸にすべきか？（初回は動画が好反応）
2. **フック言語**：損失系の煽り語（溶ける/ムダ遣い等）の強度は適切か。過度に不安を煽るリスクは？
3. **ミニマルデザイン vs 情報密度**：上品路線はTikTokの"うるさい"競合環境で埋もれないか。1枚目のインパクト設計への助言。
4. **シリーズ設計**：5本完結後の展開（続編テーマ、実演動画、事例）。フォロー転換を最大化する導線。
5. **投稿頻度・時間帯**：週2本/火金20時は妥当か。日本の非エンジニア層に最適な枠は？
6. **ハッシュタグ/発見性**：`#claudecode #ai活用` 等のタグ設計、トレンド便乗の是非。
7. **マネタイズ**：非エンジニア向けAI活用アカウントの現実的な出口（有料note/コミュニティ/案件）。
