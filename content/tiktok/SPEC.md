# TikTok コンテンツ制作 仕様書（外注用・決定版）

> 非エンジニア向け「Claude Code 活用」TikTokシリーズを、外部の制作者が本書だけで
> 一定品質で量産できるようにまとめた仕様書です。デザイン・トーン・制作フロー・
> 確定台本・納品形式を規定します。**デザインとトーンは固定。投稿ごとに変えるのは中身（文言）だけ。**

---

## 1. 目的・ターゲット

- **狙い**：非エンジニアのClaude Codeユーザーに、トークン節約・効率化ツールを1本1テーマで届け、保存・フォローを獲得する。
- **発信者**：ターゲットと同じ立場の非エンジニア個人。「同じ目線の人が教えてくれる」信頼感が武器。
- **主対象**：Claude Codeを使い始めた〜使っている非エンジニア（副業・個人開発・業務効率化）。
- **インサイト**：「便利だが料金＝トークンが増える／待ち時間が長い／専門用語が分からない」。

## 2. 実績・KPI

- 初回（トークン節約3選）を動画で投稿 → **再生2,000超・保存56**。保存率が高く、看板テーマとして有効。
- **主KPI**：保存数・保存率、フォロー転換。**副KPI**：再生数・平均視聴時間・シェア・プロフィール遷移。

## 3. 成果物（1投稿あたり・外注で作ってほしいもの）

1. **縦型スライド一式**（9:16 / 1080×1920px）… カルーセル画像 or 動画スライド
2. **キャプション**（本文・そのまま投稿できる日本語）
3. **ハッシュタグ**（7個前後・後述の基本セット＋投稿別1〜2個）
4. **導入手順テキスト**（末尾スライド or 固定コメント用）
5. （動画の場合）**ナレーション音声**（確定台本のナレーション部分を使用／AI音声可）

## 4. デザインシステム "Claude Design"（厳守・変更不可）

ミニマルで上品な編集デザイン。余白重視、装飾は最小。

**配色**
| 用途 | 値 |
|------|-----|
| 背景（ライト） | `#FAF9F5`（温かいオフホワイト） |
| 文字 | `#1F1E1C`（ほぼ黒） |
| 補助・サブ文字 | `#6B6862`（温かいグレー） |
| アクセント（1画面1箇所） | `#CC785C`（テラコッタ） |
| 罫線 | `#E8E5DE` |
| ダーク：背景 / 文字 / アクセント | `#1C1B19` / `#EDEBE4` / `#E0997B` |

**禁止**：グラデーション・影・光沢・**絵文字**・吹き出し・バッジ・囲みボックス・チェックマーク装飾。区切りは1pxヘアラインのみ。

**タイポグラフィ（差別化の核＝明朝×ゴシックの混植）**
- 名詞・キーワード・ツール名・数字＝**極太ゴシックで大きく**（主役）。
- 助詞・語尾・つなぎ＝**明朝で小さく**（脇役）。主役と脇役でサイズ差2〜3倍。
- ゴシック：Noto Sans JP / ヒラギノ角ゴ（Black〜W9）。明朝：Noto Serif JP / ヒラギノ明朝。
- 英字・数字はゴシックで統一（Montserrat等を使う場合も和文はNoto Sans JPで代替）。

**判型**：9:16。1枚1メッセージ。スマホ1画面で読み切れる文字量（各3〜4行目安）。各スライド右下に明朝の薄グレーでページ番号（例 01/04）。

## 5. スライド構成テンプレ（固定）

- **スライド1（フック）**：★最上部に「**Claude Code**」を画面最大の極太ゴシックで独立配置（1秒で"自分ごと"化）。文字は最大化＝語数は最小。損失・危機を体感させる**煽り語を1つだけ**テラコッタで強調（例：溶ける／ムダ遣い／単体運用はもう古い）。長い補足は載せない。
- **ツール紹介スライド**：左上にゴシック極太特大の連番（01/02…）→ ゴシック太大でツール名 → 明朝小グレーで1行説明 → ヘアライン → 「効果／メリット（うれしさ）／導入難易度」の3項目（ラベル＝小さな大文字ゴシック、値＝明朝、**効果の数字だけゴシック極太特大**）。
- **最終スライド（CTA）**：上部に小さな大文字ゴシックのラベル → 明朝＋ゴシック混植の手順リスト（各行間にヘアライン、ツール名はゴシック大）→ 明朝極小グレーの注記 → ミニマルなボタン2つ（塗り「保存」＋枠線「フォロー」）。

## 6. トーン＆マナー / コンプライアンス（必須）

- 効果の数値は開発者・利用者の**報告ベースの目安**。必ず「〜と言われる」「報告あり」等の**伝聞表現**を保ち、断定・誇張を足さない。
- 各ツールの**正確な導入手順は各GitHubリポジトリのREADME最新版で確認**（手順でコマンドを断定しない）。
- ツール名・URL・数値は本書の付録を正とする。実在・ライセンスは投稿前に要確認。
- **文言は確定台本を一字も変えない**（付録A）。絵文字だけはデザイン仕様により入れない。

## 7. 制作フロー & 推奨ツール

1. **固定テンプレA（デザイン指示）＋差し替えB（文言）** をAIに渡し、カルーセルHTMLを一括生成（社内資産 `TEMPLATE-prompt.md`）。デザインは常に一定。
2. HTMLを **1080×1920 のPNG**に書き出し（ブラウザのスクショ or デザインツール）。
3. 動画化は **CapCut**（無料・TikTok標準）：ページ表示秒数を設定（フック約4s／各ツール9〜10s／CTA約6s ＝約35〜40秒）、切替はディゾルブ、字幕・**AI読み上げ**を付与。
4. AIナレーション：CapCut読み上げ or **ElevenLabs**（日本語・自然）。台本のナレーション部分を使用。
5. 書き出し：縦型 1080×1920 MP4（H.264）。

> ハッシュタグ基本セット：`#claudecode #claude #ai活用 #生成ai` ＋ 投稿別に2〜3個。

## 9. 納品形式

- ファイル命名：`post-{番号}-{テーマ}/` 配下に `slide-01.png … slide-0N.png`、`video.mp4`、`caption.txt`、`hashtags.txt`、`steps.txt`。
- 画像：PNG 1080×1920（余裕があれば2160×3840の2倍）。動画：MP4 1080×1920 H.264。
- ライト/ダーク両テーマで破綻しないこと（基本はライトで書き出し）。

### A-1. 投稿2「拡張プラグイン2選」
- **フック**：Claude Code（最大）／を「単体運用」してるの、もう古いかも…／サブ：プラグインで足場を固めた人は、トークン約14%節約＋タスク成功率も上がった
- **01 superpowers**：複数のAIの動きを整理する“司令塔”プラグイン／効果：約14%トークン節約・人気上位常連・自律タスク成功率UP報告あり／うれしさ：同じ説明の繰り返しや「やり直し」が激減する！／導入のしやすさ：プラグイン一覧から追加するだけ
- **02 claude-plugins-official**：Anthropic公式のプラグイン集、安全チェックを自動化する保険役／効果：保存前に自動で危険チェック！ 手戻り＝ムダなトークンを未然にブロック／うれしさ：危ないコードの混入を代わりに見張ってくれる／導入のしやすさ：公式だから安心・超簡単
- **CTA**：まず何から始める？／① まず claude-plugins-official で安全の土台を固める ② 次に superpowers で足場をさらに強化／※数字は報告ベースの目安です。環境により変わります／今すぐプラグイン一覧チェック・試してみた結果をコメントで教えてください

### A-2. 投稿3「MCP連携3選」（絵文字なし）
- **フック**：Claude Code で Issue → PR → 報告 まで 全部自動／サブ：外部ツールと自動でつながる MCP連携を使えば、ターミナルから一歩も出ずに完結する
- **01 GitHub MCP（modelcontextprotocol / servers）**：ClaudeがGitHubを直接操作できる公式の連携ツール／効果：Issue確認 → コード修正 → PR作成 を一連で自動化できる／メリット：GitHub画面を何度も行き来する手間がなくなる／導入難易度：アクセストークンを1回設定するだけ（ふつう）
- **02 ComposioHQ / agent-orchestrator**：100種類以上の外部ツールをAIにつなぐ配線盤／効果：仕様を読む → 実装する → Slack報告 をまとめて走らせられると報告あり／メリット：NotionやSlack、Jiraを行き来する手間が減る／導入難易度：ツールごとに連携の許可設定が必要（ややむずかしい）
- **03 Claude Code GitHub Actions**：自分のPCではなくGitHub上でClaudeを自動起動させる仕組み／効果：PR作成をきっかけに自動レビュー・改善提案が走る／メリット：PCを閉じていてもチェックが回り続ける／導入難易度：公開テンプレートをコピーして鍵を設定するだけ（ふつう）
- **CTA**：まず何から始める？／① まず GitHub MCP で Issue → PR の自動化を試す ② 慣れたら Composio で 他ツールとの接続を広げる ③ チームや常時監視なら GitHub Actions を導入／数字は報告ベースの目安です。環境により変わります／まずは GitHub MCP から試してみてください。実際に試した結果をコメントで教えてください
